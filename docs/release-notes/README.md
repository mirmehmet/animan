# Release notes

The release workflow uses `vX.Y.Z.md` from this folder as the GitHub release text for tag `vX.Y.Z`. Without a file, GitHub's generated list of changes is used instead.

Write the file before pushing the tag, in the same three sections as earlier releases:

```markdown
## What's new in vX.Y.Z

- **Short title** — what changed for the user.

## Fixes

- What was wrong, and what happens now.

## Upgrading

- Anything to know when moving from the previous version (data, backups, settings).
```
